Why it's different

Zero data custody. Zero AI cost. Yours end to end.

01 — own the data

It's your Supabase

Surveys, questions, and responses live in your own Supabase project. The author's infrastructure stores nothing — there's no database to leak.

02 — own the cost

Your agent does the work

Survey authoring and analysis run inside your agent. There's no AI on the server side, so you carry your own AI cost — and nothing else.

03 — own the keys

Keys stay local

Your Supabase secret key lives in local config on your machine — never transmitted, never logged, never a tool argument the agent can see.

How it works

Three pieces, one source of truth

Your agent drives the MCP server to build and publish a survey. Publishing returns a share link; a respondent opens it, and the stateless page-service writes their submission straight into your Supabase. Then your agent reads the results.

  Your AI agent  ──(MCP / stdio)──▶  mcp-server ──┐
                                                ├──▶  your Supabase
  Respondent  ──(browser)──▶  page-service ──┘      (store of record)
schema — SQL + shared types core — pure survey logic mcp-server — 12 tools + CLI page-service — Next.js public page

Quick start

Connect your agent in two minutes

Works with any MCP-capable client. First connect your Supabase (above), then point your client at the server.

1

Install the schema & store your keys

In your terminal — your keys are typed in and stored locally, never sent to the agent.

# paste the printed SQL into the Supabase SQL editor, then:
npx -y @agentic-survey/mcp-server init
2

Point your client at the server

Pick your client:

claude mcp add agentic-survey -- npx -y @agentic-survey/mcp-server
// claude_desktop_config.json
{
  "mcpServers": {
    "agentic-survey": { "command": "npx", "args": ["-y", "@agentic-survey/mcp-server"] }
  }
}
// .cursor/mcp.json (or your client's MCP config)
{
  "mcpServers": {
    "agentic-survey": { "command": "npx", "args": ["-y", "@agentic-survey/mcp-server"] }
  }
}
3

Just talk to your agent

It chains the tools for you — create_survey → add_question → publish_survey → get_results.

“Build a 4-question customer-satisfaction survey with a 1–5 rating,
 a yes/no, a multiple choice, and an open comment. Publish it and
 give me the share link.”

“Summarise the results so far — themes from the comments too.”
